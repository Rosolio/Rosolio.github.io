## 一、多线程基础

### 1.Java内存模型(JMM)

1. 核心作用：规范多线程共享变量读写，解决**可见性、原子性、有序性**三大问题
2. 内存划分：主内存(共享变量)、线程本地工作内存(CPU缓存副本)
3. 三大特性拆解
  - 可见性：线程修改后立刻刷入主存，volatile实现
  - 原子性：操作不可拆分，synchronized/Lock/Atomic类保证
  - 有序性：禁止指令重排，volatile内存屏障、happens-before规则约束
4. 指令重排：编译器/CPU为优化性能打乱代码顺序，单线程无影响，多线程会出空指针、数据错乱

### 2.什么是多线程，注意事项

1. 定义：单进程内多条执行流，共享堆/方法区，独有程序计数器、虚拟机栈
2. 三大风险：线程安全(数据竞争)、线程通信阻塞、频繁创建销毁损耗性能(用线程池优化)

### 3.Java线程与操作系统线程区别

1. 平台线程(JDK21前)：1:1模型，一个Java线程对应OS pthread，栈默认1MB，创建开销大
2. 虚拟线程(JDK21+ JEP444)：M:N模型，少量载体线程承载百万虚拟线程，栈动态伸缩，IO场景零阻塞
3. Go协程vsJava虚拟线程：Go原生M:N，Java21虚拟线程才对齐该模型

### 4.多线程三大安全特性(原子/可见/有序)

- **原子性**：synchronized、ReentrantLock、Atomic原子类
- **可见性**：volatile、synchronized(释放时刷新缓存)
- **有序性**：volatile内存屏障、happens-before

### 5.保证数据一致性方案

1. 悲观锁：synchronized、ReentrantLock，操作前加锁独占资源
2. 乐观锁：CAS、版本号机制，无锁，更新校验数据是否被修改
3. 数据库事务AC(底层数据库锁)

### 6.线程四种创建方式

#### （1）继承Thread类

```
class MyThread extends Thread{
    @Override
    public void run(){
        System.out.println("线程执行");
    }
}
public static void main(){
    MyThread t = new MyThread();
    t.start(); // start才创建内核线程，run只是普通方法
}
```

优点：直接this获取当前线程；缺点：单继承限制

#### （2）实现Runnable接口

```
class MyRun implements Runnable{
    @Override
    public void run(){
        System.out.println("执行任务");
    }
}
public static void main(){
    Thread t = new Thread(new MyRun());
    t.start();
}
```

优点：可多实现、多线程共享任务对象；缺点：需Thread.currentThread()

#### （3）Callable+FutureTask（有返回、抛异常）

```
class MyCall implements Callable<Integer>{
    @Override
    public Integer call() throws Exception{
        return 100;
    }
}
public static void main() throws Exception{
    FutureTask<Integer> task = new FutureTask<>(new MyCall());
    new Thread(task).start();
    Integer res = task.get(); // 阻塞获取结果
}
```

#### （4）线程池Executor

```
ExecutorService pool = Executors.newFixedThreadPool(5);
pool.submit(()->System.out.println("任务"));
pool.shutdown();
```

### 7.启动线程：start() vs run()

- start()：调用native方法创建OS线程，触发run执行，只能调用一次
- run()：普通成员方法，直接调用不会新开线程

### 8.停止线程正确方式（废弃stop()）

1. 共享volatile标志位

```
class Task implements Runnable{
    private volatile boolean flag = true;
    @Override
    public void run(){
        while(flag){}
    }
    public void stop(){flag = false;}
}
```

2. interrupt中断机制

```
Thread t = new Thread(()->{
    while(!Thread.currentThread().isInterrupted()){}
});
t.start();
t.interrupt();
```

3. Future.cancel(true)：线程池任务中断
4. 特殊IO阻塞：关闭资源解除阻塞
   禁止：Thread.stop() 暴力终止，破坏对象状态

### 9.interrupt原理

1. 仅修改线程中断标记，不会直接终止线程
2. 线程处于sleep/wait/join阻塞：抛出InterruptedException，自动清除中断标记
3. 运行中线程：仅标记，需手动isInterrupted()判断退出

### 10.Java六大线程状态(NEW/RUNNABLE/BLOCKED/WAITING/TIMED\_WAITING/TERMINATED)

1. NEW：new Thread未调用start
2. RUNNABLE：就绪+运行，等待CPU调度/正在执行
3. BLOCKED：竞争synchronized锁失败阻塞
4. WAITING：无限等待(wait()/join()/park())，需主动唤醒
5. TIMED\_WAITING：限时等待(sleep/wait(long))
6. TERMINATED：线程执行完毕

### 11.sleep()与wait()区别

| 维度   | sleep()    | wait()             |
|------|------------|--------------------|
| 所属类  | Thread静态方法 | Object实例方法         |
| 锁    | 不释放锁       | 释放当前对象锁            |
| 调用位置 | 任意代码       | 必须在同步块内            |
| 唤醒   | 时间到自动就绪    | notify/notifyAll唤醒 |
| 用途   | 单纯暂停线程     | 线程间协作              |

### 12.sleep是否释放CPU

释放CPU时间片，进入TIMED\_WAITING，但**不释放任何锁**

### 13.BLOCKED与WAITING区别

1. BLOCKED：竞争同步锁失败被动阻塞，锁释放自动竞争
2. WAITING：主动调用wait/park进入，必须手动notify唤醒

### 14.wait线程如何恢复RUNNABLE

同一锁对象调用notify()/notifyAll()，唤醒后重新竞争锁

### 15.notify vs notifyAll

1. notify：随机(HotSpot FIFO)唤醒一个等待线程，其余继续等待，可能永久休眠
2. notifyAll：唤醒所有等待线程，全部重新竞争锁，无线程饿死风险，生产推荐

### 16.线程间通信四种方式

1. volatile共享变量（轻量）

```
volatile boolean flag = false;
```

2. wait/notify 同步锁协作
3. Lock+Condition（多条件精准唤醒）

```
ReentrantLock lock = new ReentrantLock();
Condition cond = lock.newCondition();
```

4. BlockingQueue阻塞队列（生产者消费者）

```
BlockingQueue<Integer> q = new LinkedBlockingQueue<>();
q.put(1);
q.take();
```

### 18.Go协程vs Java线程/虚拟线程

1. 调度：Go GMP M:N用户态调度；旧Java 1:1内核线程，Java21虚拟线程M:N
2. 内存：goroutine初始2KB栈；平台线程1MB，虚拟线程极小
3. 通信：Go Channel；Java共享内存+锁/工具类

1. 线程池：ThreadPoolExecutor、Executors

3. 同步工具：CountDownLatch、CyclicBarrier、Semaphore
4. 原子类：AtomicInteger、AtomicStampedReference

4. Atomic原子类无锁CAS

### 6.synchronized vs ReentrantLock

<mark>
1. 语法：synchronized关键字自动释放；Lock手动lock/unlock+finally  
2. 锁类型：synchronized仅非公平；Lock支持公平/非公平  
3. 功能：Lock支持可中断、限时等待、多Condition  
4. 底层：synchronized JVM监视器锁(锁升级)；Lock基于AQS
</mark>

### 7.synchronized静态方法vs普通方法

1. 普通同步方法：锁当前实例this，多实例互不阻塞
2. 静态同步方法：锁类Class对象，所有实例互斥

### 8.可重入锁原理

同一线程多次获取同一锁，AQS state计数器累加，释放递减至0才完全解锁
synchronized、ReentrantLock均支持可重入

### 9.synchronized锁升级流程（JDK1.6+）

<mark>无锁 → 偏向锁 → 轻量级锁 → 重量级锁（单向不可逆）

1. 偏向锁：单线程无竞争，标记线程ID，JDK15默认关闭
2. 轻量级锁：少量竞争，自旋CAS避免内核切换
3. 重量级锁：竞争激烈，OS互斥量，线程阻塞</mark>

### 10.JVM对synchronized四大优化

锁升级、锁消除(逃逸分析)、锁粗化、自适应自旋

### 11.AQS原理

<mark>1. 核心三要素：volatile state同步状态、FIFO双向等待队列、tryAcquire/tryRelease模板方法
2. state含义：ReentrantLock是锁重入次数；CountDownLatch是剩余计数；Semaphore是许可数
3. 线程抢锁失败封装Node入队，阻塞；释放时唤醒队首线程</mark>

### 12.CAS与AQS关系

AQS修改state全部依赖CAS原子操作；CAS是AQS底层原子保障

### 13.AQS实现公平可重入锁完整代码

```
import java.util.concurrent.locks.AbstractQueuedSynchronizer;
import java.util.concurrent.locks.Condition;

public class FairLock {
    private Sync sync = new Sync();
    static class Sync extends AbstractQueuedSynchronizer{
        @Override
        protected boolean tryAcquire(int arg) {
            int c = getState();
            Thread curr = Thread.currentThread();
            if(c == 0){
                // 公平：判断有无前驱等待线程
                if(!hasQueuedPredecessors() && compareAndSetState(0,1)){
                    setExclusiveOwnerThread(curr);
                    return true;
                }
            }else if(getExclusiveOwnerThread() == curr){
                setState(c+1);
                return true;
            }
            return false;
        }
        @Override
        protected boolean tryRelease(int arg) {
            int c = getState()-1;
            if(Thread.currentThread() != getExclusiveOwnerThread())
                throw new IllegalMonitorStateException();
            boolean free = c == 0;
            if(free) setExclusiveOwnerThread(null);
            setState(c);
            return free;
        }
        Condition newCond(){return new ConditionObject();}
    }
    public void lock(){sync.acquire(1);}
    public void unlock(){sync.release(1);}
}
```

### 14.ThreadLocal

<mark>
1. 作用：线程私有变量，消除共享竞争，不用锁
2. 底层：每个Thread持有ThreadLocalMap；key是弱引用ThreadLocal，value强引用业务对象
3. 内存泄漏根源：GC回收key后value无法访问，线程池长期复用残留对象
4. 解决方案：使用完手动调用remove()
</mark>

### 15.乐观锁vs悲观锁

悲观锁：默认会冲突，操作前加锁(synchronized/Lock)
乐观锁：默认无冲突，CAS更新，失败重试(Atomic类)

### 16.CAS三大缺点

<mark>1. ABA问题：值A→B→A，CAS无法识别中间修改，用AtomicStampedReference加版本号解决</mark>

```
AtomicStampedReference<Integer> ref = new AtomicStampedReference(10,0);
ref.compareAndSet(10,20,0,1);
```

<mark>2. 自旋空转，高并发CPU暴涨
3. 仅支持单个变量原子操作，多变量需锁</mark>

### 17.volatile关键字两大作用

<mark>1. 可见性：写立即刷入主存，读强制从主存加载
2. 内存屏障禁止指令重排
   缺陷：不保证原子性（i++复合操作不安全）</mark>

### 18.公平锁/非公平锁

公平锁：按等待队列顺序获取，吞吐低，无饥饿
非公平锁：线程直接插队抢锁，吞吐高，可能线程饥饿
synchronized是非公平锁；ReentrantLock可构造传true开启公平

### 19.死锁四大必要条件（全部满足才死锁）

<mark>1. 互斥：资源独占
2. 持有并等待：持有资源同时申请其他资源
3. 不可剥夺：资源不能强制回收
4. 循环等待：线程资源形成环形依赖
   破坏方案：统一资源申请顺序（打破循环等待）</mark>
   死锁示例代码

```
Object r1 = new Object(),r2 = new Object();
new Thread(()->{
    synchronized(r1){
        Thread.sleep(100);
        synchronized(r2){}
    }
}).start();
new Thread(()->{
    synchronized(r2){
        Thread.sleep(100);
        synchronized(r1){}
    }
}).start();
```

## 三、线程池

### 1.线程池七大核心参数

<mark>1. corePoolSize：核心线程（常驻不销毁）
2. maximumPoolSize：最大线程总数（核心+临时线程）
3. keepAliveTime：临时线程空闲销毁时长
4. TimeUnit：时间单位
5. workQueue：阻塞队列，存储等待任务
6. threadFactory：线程工厂，自定义线程名
7. handler：队列+线程满载拒绝策略</mark>

### 2.线程池执行流程

<mark>1. 新任务提交，线程数 < corePoolSize → 创建核心线程执行
2. 核心线程已满 → 任务入阻塞队列
3. 队列满 → 创建临时线程，总线程<maxPoolSize
4. 线程达最大值+队列满 → 执行拒绝策略</mark>

### 3.四种内置拒绝策略

<mark>1. AbortPolicy(默认)：抛RejectedExecutionException
2. CallerRunsPolicy：提交任务主线程执行（降级）
3. DiscardPolicy：静默丢弃任务
4. DiscardOldestPolicy：丢弃队列最旧任务，重试提交</mark>

### 4.四类Executors自带线程池（阿里规范禁止使用）

<mark>1. FixedThreadPool：固定线程，无界队列OOM风险
2. CachedThreadPool：无上限线程，瞬时并发创建大量线程
3. SingleThreadExecutor：单线程有序执行，无界队列
4. ScheduledThreadPool：定时任务，无界延迟队列
   生产规范：手动new ThreadPoolExecutor，指定有界队列、合理线程数</mark>

### 5.核心线程数配置经验

CPU密集：核心线程 = CPU核心数+1
IO密集：核心线程 = CPU核心数\*2（IO阻塞多，多线程并行）

### 6.shutdown() vs shutdownNow()

1. shutdown()：停止接收新任务，已提交任务全部执行，空闲线程中断
2. shutdownNow()：中断运行线程，清空队列，返回未执行任务List

### 7.取消线程池任务

submit返回Future对象，调用future.cancel(boolean)
true：中断运行中任务；false仅取消未开始任务

```
ExecutorService pool = Executors.newSingleThreadExecutor();
Future<?> f = pool.submit(()->{
    Thread.sleep(5000);
});
f.cancel(true);
```

### 8.线程池用到的设计模式

享元(复用线程)、生产者消费者(任务队列)、工厂、模板方法

### 2.DCL双重检查锁单例（volatile作用）

```
public class Singleton{
    // volatile禁止指令重排，避免半初始化对象暴露
    private static volatile Singleton instance;
    private Singleton(){}
    public static Singleton getInstance(){
        if(instance == null){
            synchronized(Singleton.class){
                if(instance == null){
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

instance = new Singleton()分三步：分配内存、初始化对象、赋值引用；无volatile会重排为先赋值后初始化，其他线程拿到空对象

### 4.两线程各循环50次自增（线程不安全示例）

```

```
