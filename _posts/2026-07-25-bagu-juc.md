## 一、多线程基础

### 1.Java内存模型(JMM)

Java内存模型定义了程序中各种变量的访问规则：

- 所有变量都存储在主存，每个线程都有自己的工作内存。
- 工作内存中保存了被该线程使用的变量的主存副本，线程对变量的所有操作都必须在工作空间进行，不能直接读写主内存数据。
- 操作完成后，线程的工作内存通过缓存一致性协议将操作完的数据刷回主存。

#### 三大特性拆解

- 可见性：线程修改共享变量后，其他线程能**立刻得知修改**，volatile/synchronized/final都能保证可见性
- 原子性：**操作不可拆分**，要么都执行（不被打断）要么都不执行，synchronized/Lock/Atomic类保证
- 有序性：虽然多线程存在并发和指令优化等操作，但是在**本线程内**观察该线程的所有执行操作都是**有序**
  的，volatile内存屏障、happens-before规则约束

#### 简述happens-before八大规则

1. 程序次序规则：一个线程内，按照代码顺序，书写在前面的操作先行发生于书写在后面的操作；
2. 锁定规则：一个unLock操作先行发生于后面对同一个锁的lock操作；
3. volatile变量规则：对一个变量的写操作先行发生于后面对这个变量的读操作；
4. 传递规则：如果操作A先行发生于操作B，而操作B又先行发生于操作C，则可以得出操作A先行发生于操作C；
5. 线程启动规则：Thread对象的start()方法先行发生于此线程的每个一个动作；
6. 线程中断规则：对线程interrupt()方法的调用先行发生于被中断线程的代码检测到中断事件的发生；
7. 线程终结规则：线程中所有的操作都先行发生于线程的终止检测，我们可以通过Thread.join()方法结束、Thread.isAlive()
   的返回值手段检测到线程已经终止执行；
8. 对象终结规则：一个对象的初始化完成先行发生于他的finalize()方法的开始；

### 2.什么是多线程，注意事项

1. 定义：单进程内多条执行流，共享堆/方法区，独有程序计数器、虚拟机栈
2. 三大风险：线程安全(数据竞争)、线程通信阻塞、频繁创建销毁损耗性能(用线程池优化)

### 3.Java线程与操作系统线程区别

1. 平台线程(JDK21前)：1:1模型，一个Java线程对应OS pthread，栈默认1MB，创建开销大
2. 虚拟线程(JDK21+ JEP444)：M:N模型，少量载体线程承载百万虚拟线程，栈动态伸缩，IO场景零阻塞
3. Go协程vsJava虚拟线程：Go原生M:N，Java21虚拟线程才对齐该模型

### 4.多线程三大安全特性(原子/可见/有序)

- **原子性**：synchronized、ReentrantLock、Atomic原子类
- **可见性**：volatile、synchronized(释放时刷新缓存)
- **有序性**：volatile内存屏障、happens-before

### 5.保证数据一致性方案

1. 悲观锁：synchronized、ReentrantLock，操作前加锁独占资源
2. 乐观锁：CAS、版本号机制，无锁，更新校验数据是否被修改
3. 数据库事务AC(底层数据库锁)

### 6.线程四种创建方式

#### （1）继承Thread类

### 10.Java六大线程状态(NEW/RUNNABLE/BLOCKED/WAITING/TIMED\_WAITING/TERMINATED)

1. NEW：new Thread未调用start
2. RUNNABLE：就绪+运行，等待CPU调度/正在执行
3. BLOCKED：竞争synchronized锁失败阻塞
4. WAITING：无限等待(wait()/join()/park())，需主动唤醒
5. TIMED\_WAITING：限时等待(sleep/wait(long))
6. TERMINATED：线程执行完毕

### 11.sleep()与wait()区别

| 维度   | sleep()    | wait()             |
|------|------------|--------------------|
| 所属类  | Thread静态方法 | Object实例方法         |
| 锁    | 不释放锁       | 释放当前对象锁            |
| 调用位置 | 任意代码       | 必须在同步块内            |
| 唤醒   | 时间到自动就绪    | notify/notifyAll唤醒 |
| 用途   | 单纯暂停线程     | 线程间协作              |

### 12.sleep是否释放CPU

释放CPU时间片，进入TIMED\_WAITING，但**不释放任何锁**

### 13.BLOCKED与WAITING区别

1. BLOCKED：竞争同步锁失败被动阻塞，锁释放自动竞争
2. WAITING：主动调用wait/park进入，必须手动notify唤醒

### 14.wait线程如何恢复RUNNABLE

同一锁对象调用notify()/notifyAll()，唤醒后重新竞争锁

### 15.notify vs notifyAll

1. notify：随机(HotSpot FIFO)唤醒一个等待线程，其余继续等待，可能永久休眠
2. notifyAll：唤醒所有等待线程，全部重新竞争锁，无线程饿死风险，生产推荐

### 4.锁代码示例

#### synchronized

```
// 同步方法
public synchronized void inc(){count++;}
// 同步代码块
Object lock = new Object();
void test(){
    synchronized(lock){}
}
```

使用synchronized关键字会在代码前后加上monitorenter和monitorexit指令。  
monitorenter指令会在代码块执行前获取锁，如果对象没有被锁定或已经获得了锁，计数器加一，其他竞争锁的进程进入等待队列；  
monitorexit指令会在代码块执行后释放锁，计数器减一，如果计数器为零，表示没有线程持有锁，等待队列进程可以抢锁。  
-- 简单同步需求/代码块同步/内置锁使用（尤其是对象的状态与锁保护的代码紧密相关时）

#### ReentrantLock

```
ReentrantLock lock = new ReentrantLock();
void add(){
    lock.lock();
    try{ count++; }
    finally{ lock.unlock(); } // 必须finally释放
}
```

ReentrantLock是一个可重入锁，底层基于AQS实现，支持公平/非公平锁、可中断、限时等待、多Condition。
可重入性：同一线程可以多次获取同一锁，AQS state计数器累加，释放递减至0才完全解锁

#### 读写锁

```
ReentrantReadWriteLock rw = new ReentrantReadWriteLock();
Lock read = rw.readLock();
Lock write = rw.writeLock();
```

### 9.synchronized锁升级流程（JDK1.6+）

<mark>无锁 → 偏向锁 → 轻量级锁 → 重量级锁（单向不可逆）

1. 偏向锁：开发者发现多数情况下锁不存在竞争，一把锁往往是由同一个线程获得的。偏向锁不会主动释放，这样每次偏向锁进入的时候都会**判断该资源是否偏向自己**（通过比较目前请求锁的**线程ID**是否和偏向锁本身记录的ID**一致**），如果是就可以直接进入同步操作
  - 若线程id**不一致**，利用**cas**将对象的**markword**进行更改，使线程id部分**换成本线程id**。更换成功，则重偏向完成，获得偏向锁，失败则说明有多线程竞争，**升级为轻量级锁**。
2. 轻量级锁：在没有竞争的前提下减少重量级锁出现导致的性能消耗
  - 若对象没有被锁定，虚拟机将在当前线程的栈帧中建立一条**锁记录**，存储锁对象**markword的拷贝**，使用cas尝试把markword**更新为指向锁记录的指针**。更新成功则说明持有锁，**锁标志位变为00**，表示处于轻量级锁状态。
  - **更新失败**则说明至少存在一条线程与当前线程竞争，虚拟机会检查markword是否指向本线程的本线程的栈帧。如果是，则说明本线程已经持有锁，直接进入同步块执行
  - 如果不是则说明锁已被其他线程抢占，轻量级锁不再有效，膨胀为重量级锁，锁标志位变为10，此时的markword存储的就是指向重量级锁的指针，后面等待锁的进程也将阻塞
3. 重量级锁：就是传统的synchronized实现，依赖操作系统的互斥量mutex实现，markword指向monitor对象。
  - 未获取锁的线程会被阻塞，进入monitor的等待队列。该过程需从用户态切换到内核态，由os调度线程的阻塞和唤醒，开销很大
  - 但是在竞争激烈、锁持续时间长的情景下，阻塞线程反而比自旋更节省cpu资源，这就是为什么要升级为重量级锁

### 11.AQS原理

AQS（AbstractQuenedSynchronizer）抽象的队列式同步器。AQS是将每一条请求共享资源的线程封装成一个锁队列的一个结点（Node），来实现锁的分配。AQS是用来构建锁或其他同步组件的基础框架，它使用一个
volatile int state 变量作为共享资源，如果线程获取资源失败，则进入同步队列（双向FIFO队列）等待；如果获取成功就执行临界区代码，释放资源时会通知同步队列中的等待线程。

子类通过继承同步器并实现它的抽象方法getState、setState 和 compareAndSetState对同步状态进行更改。

AQS获取独占锁/释放独占锁原理：

获取：（acquire）

调用 tryAcquire 方法安全地获取线程同步状态，获取失败的线程会被构造同步节点并通过 addWaiter 方法加入到同步队列的尾部，在队列中自旋。
调用 acquireQueued 方法使得该节点以死循环的方式获取同步状态，如果获取不到则阻塞。
释放：（release）

调用 tryRelease 方法释放同步状态
调用 unparkSuccessor 方法唤醒头节点的后继节点，使后继节点重新尝试获取同步状态。
AQS获取共享锁/释放共享锁原理

获取锁（acquireShared）

调用 tryAcquireShared 方法尝试获取同步状态，返回值不小于 0 表示能获取同步状态。
释放（releaseShared），并唤醒后续处于等待状态的节点。

### 12.CAS与AQS关系

AQS修改state全部依赖CAS原子操作；CAS是AQS底层原子保障

### 13.AQS实现公平可重入锁完整代码

```
import java.util.concurrent.locks.AbstractQueuedSynchronizer;
import java.util.concurrent.locks.Condition;

public class FairLock {
    private Sync sync = new Sync();
    static class Sync extends AbstractQueuedSynchronizer{
        @Override
        protected boolean tryAcquire(int arg) {
            int c = getState();
            Thread curr = Thread.currentThread();
            if(c == 0){
                // 公平：判断有无前驱等待线程
                if(!hasQueuedPredecessors() && compareAndSetState(0,1)){
                    setExclusiveOwnerThread(curr);
                    return true;
                }
            }else if(getExclusiveOwnerThread() == curr){
                setState(c+1);
                return true;
            }
            return false;
        }
        @Override
        protected boolean tryRelease(int arg) {
            int c = getState()-1;
            if(Thread.currentThread() != getExclusiveOwnerThread())
                throw new IllegalMonitorStateException();
            boolean free = c == 0;
            if(free) setExclusiveOwnerThread(null);
            setState(c);
            return free;
        }
        Condition newCond(){return new ConditionObject();}
    }
    public void lock(){sync.acquire(1);}
    public void unlock(){sync.release(1);}
}
```

### 14.ThreadLocal

![threadloacl](/assets/img/bagu/threadlocal.png)

1. 作用：让每个线程都有一份自己的变量副本；不同线程读写，操作的是自己线程内的副本，**线程隔离，不存在线程安全问题**。
2. 底层：每个Thread持有ThreadLocalMap(内部维护一个entry数组)；key是弱引用ThreadLocal，value强引用业务对象
3. 内存泄漏根源：entry的key是对threadlocal的弱引用，而value是强引用，GC回收key后value无法访问，如果线程被线程池长期复用却不再访问这个threadlocal对象，value就会一直驻留
4. 解决方案：使用完手动调用remove()

### 15.乐观锁vs悲观锁

悲观锁：默认会冲突，操作前加锁(synchronized/Lock)
乐观锁：默认无冲突，CAS更新，失败重试(Atomic类)

### 16.CAS原理&三大缺点

#### CAS原理(compare-and-swap)：‌

1. 比较‌：线程读取内存中的**当前值 V**，并与自己**预期的旧值 A** 进行比较 。
2. 交换‌：如果 V 和 A 相等，说明期间没有其他线程修改过，就原子性地将 V 更新为**新值 B** 。
3. 重试‌：如果 V 和 A 不相等，说明数据已被修改，操作失败，线程不会阻塞挂起，而是会循环重试直到成功，这个过程称为**自旋** 。

<mark>1. ABA问题</mark>：值A→B→A，CAS无法识别中间修改，用AtomicStampedReference加版本号解决

```
AtomicStampedReference<Integer> ref = new AtomicStampedReference(10,0);
ref.compareAndSet(10,20,0,1);
```

2. 自旋空转，高并发CPU暴涨
3. 仅支持单个变量原子操作，多变量需锁</mark>

### 17.volatile关键字两大作用

1. 可见性：写立即刷入主存，读强制从主存加载(其他线程可立即得知修改)
2. 内存屏障禁止指令重排  
   **缺陷**：不保证原子性（volatile 只能保证**单次读 / 写**是原子；**复合操作（读‑改‑写，例如i++）不是原子**。）

> 指令重排：编译器/CPU为优化性能打乱代码顺序，单线程无影响，多线程会出空指针、数据错乱

### 18.公平锁/非公平锁

公平锁：按等待队列顺序获取，吞吐低，无饥饿
非公平锁：线程直接插队抢锁，吞吐高，可能线程饥饿
synchronized是非公平锁；ReentrantLock可构造传true开启公平

### 19.死锁四大必要条件（全部满足才死锁）

1. 互斥：资源独占
2. 持有并等待：持有资源同时申请其他资源
3. 不可剥夺：资源不能强制回收
4. 循环等待：线程资源形成环形依赖
   破坏方案：统一资源申请顺序（打破循环等待）
   死锁示例代码

```
Object r1 = new Object(),r2 = new Object();
new Thread(()->{
    synchronized(r1){
        Thread.sleep(100);
        synchronized(r2){}
    }
}).start();
new Thread(()->{
    synchronized(r2){
        Thread.sleep(100);
        synchronized(r1){}
    }
}).start();
```

## 三、线程池

> <mark>核心作用：复用线程，控制并发数，避免频繁创建销毁线程开销</mark>

### 1.线程池七大核心参数

1. corePoolSize：核心线程（常驻不销毁）
2. maximumPoolSize：最大线程总数（核心+临时线程）
3. keepAliveTime：临时线程空闲销毁时长
4. TimeUnit：时间单位
5. workQueue：阻塞队列，存储等待任务
6. threadFactory：线程工厂，用来生产一组相同任务的线程。
7. handler：队列+线程满载拒绝策略

### 2.线程池执行流程

1. 新任务提交，线程数 < corePoolSize → 创建核心线程执行
2. 核心线程已满 → 任务入阻塞队列
3. 队列满 → 创建临时线程，总线程<maxPoolSize
4. 线程达最大值+队列满 → 执行拒绝策略

### 3.四种内置拒绝策略

1. AbortPolicy(默认)：抛RejectedExecutionException，丢弃任务
2. CallerRunsPolicy：提交任务的线程自己执行任务，除非线程池被停止或队列有空缺
3. DiscardPolicy：静默丢弃任务
4. DiscardOldestPolicy：丢弃队列最旧任务，重试提交

### 4.四类Executors自带线程池

1. FixedThreadPool：**固定**线程（核心线程数等于最大线程数），**无界队列**OOM风险
2. CachedThreadPool：**无上限**线程（maximumPoolSize被设置为INT_MAX），瞬时**并发创建大量线程**导致OOM
3. SingleThreadExecutor：**单线程**有序执行，无界队列
4. ScheduledThreadPool：**定时**任务，无界延迟队列
   生产规范：手动new ThreadPoolExecutor，指定有界队列、合理线程数

### 5.核心线程数配置经验

**CPU密集**：核心线程 = CPU核心数+1  
**IO密集**：核心线程 = CPU核心数*2（IO阻塞多，多线程并行）

### 6.shutdown() vs shutdownNow()

1. shutdown()：停止接收新任务，已提交任务全部执行，空闲线程中断
2. shutdownNow()：中断运行线程，清空队列，返回未执行任务List

### 7.取消线程池任务

submit返回Future对象，调用future.cancel(boolean)
true：中断运行中任务；false仅取消未开始任务

```
ExecutorService pool = Executors.newSingleThreadExecutor();
Future<?> f = pool.submit(()->{
    Thread.sleep(5000);
});
f.cancel(true);
```

### 8.线程池用到的设计模式

享元(复用线程)、生产者消费者(任务队列)、工厂、模板方法

## 四、并发面试场景代码题

### 1.双线程交替打印奇偶

```
Object lock = new Object();
int num = 1;
int max = 10;
// 奇数线程
new Thread(()->{
    synchronized(lock){
        while(num <= max){
            if(num%2 !=0){
                System.out.println(num++);
                lock.notify();
            }else{
                try{lock.wait();}catch(Exception e){}
            }
        }
    }
}).start();
// 偶数线程
new Thread(()->{
    synchronized(lock){
        while(num <= max){
            if(num%2 ==0){
                System.out.println(num++);
                lock.notify();
            }else{
                try{lock.wait();}catch(Exception e){}
            }
        }
    }
}).start();
```

### 2.DCL双重检查锁单例（volatile作用）

```
public class Singleton{
    // volatile禁止指令重排，避免半初始化对象暴露
    private static volatile Singleton instance;
    private Singleton(){}
    public static Singleton getInstance(){
        if(instance == null){
            synchronized(Singleton.class){
                if(instance == null){
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

instance = new Singleton()分三步：分配内存、初始化对象、赋值引用；无volatile会重排为先赋值后初始化，其他线程拿到空对象

### 3.3线程执行完再执行主线程CountDownLatch

```
CountDownLatch latch = new CountDownLatch(3);
for(int i=0;i<3;i++){
    new Thread(()->{
        try{Thread.sleep(1000);}catch(Exception e){}
        latch.countDown();
    }).start();
}
latch.await();
System.out.println("全部完成");
```

### 4.两线程各循环50次自增（线程不安全示例）

```
int num = 0;
Runnable task = ()->{
    for(int i=0;i<50;i++){
        num++;
    }
};
new Thread(task).start();
new Thread(task).start();
// 结果小于100，num++非原子
```

原子类安全写法：

```
AtomicInteger num = new AtomicInteger(0);
Runnable task = ()->{
    for(int i=0;i<50;i++) num.incrementAndGet();
};
```
